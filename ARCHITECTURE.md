The app was built with Vite + React + TypeScript to keep it simple, with no third-party component libraries. The architecture selected is component-based since the domain was small. I could use feature-based architecture if we needed to maintain a larger project. For app state, given that we have to support actions linked with state changes, useReducer provides better maintainability than useState for this type of complex state logic that involves multiple sub-values. I place a dedicated reducer folder for reducers like notesReducer.

Regarding scalability decisions: for this exercise, state is managed locally in App and passed down via props, which is sufficient for a single-board experience. In a larger application with multiple views or components needing access to notes state, I would introduce Redux/Zustand over React Context. Since the board mutates frequently — notes are constantly created, moved, resized and deleted — Context would trigger re-renders across the entire component tree on every change, which would hurt performance significantly. Zustand's subscription model allows components to subscribe only to the slices of state they need.

Regarding drag and drop and resizing: I chose the native DnD API to move notes and manage data transfer across the board, which is useful when deleting notes and reading the note id from the drop event. For resizing, mouse events give precise control over pixel-level positioning, which the native drag API doesn't provide.

Lastly, for persistence and performance: I added a storage utility relying on localStorage to persist notes across sessions. useCallback is used for reference stabilization, and memoizing the Note component prevents unnecessary re-renders when unrelated state changes occur in the parent, such as creating or deleting other notes.
